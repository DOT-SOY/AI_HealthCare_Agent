# 결제 완료 후 503 오류 발생 원인 분석

## 현상
토스 결제가 정상 완료되었는데도, 결제 완료 페이지에서 가끔 **503 오류**가 화면에 표시되는 경우가 있음.

---

## 원인

### 1. 토스 측 “처리 중” 응답 (S008)

**흐름**
1. 사용자가 토스 결제창에서 결제 완료 → 토스가 **성공 URL**로 리다이렉트 (paymentKey, orderId, amount 전달).
2. 우리 **결제 완료 페이지**가 로드되면 곧바로 **결제 승인 API** (`POST /api/payments/toss/confirm`)를 호출.
3. 백엔드가 **토스 승인 API** (`POST https://api.tosspayments.com/v1/payments/confirm`)를 호출.
4. 이때 토스가 아직 내부 처리 중이면 **S008** 또는 “기존 요청을 처리중”, “FAILED_PAYMENT_INTERNAL_SYSTEM_PROCESSING” 등의 응답을 줄 수 있음 (결제는 됐지만 승인 처리 지연).

**백엔드 처리** (`PaymentServiceImpl.callTossConfirmApi`)

- 위와 같은 메시지를 **`SHOP_PAYMENT_PROCESSING_RETRY`** 로 매핑.
- 이 에러 코드는 **HTTP 503 Service Unavailable** 로 응답하며, 메시지는  
  `"결제가 처리 중입니다. 잠시 후 다시 시도해 주세요. (토스: [S008])"`.

→ 즉, **결제는 된 상태**인데, 승인 API 호출 타이밍에 따라 토스가 “처리 중”을 반환하고, 우리는 이를 **503**으로 내려주는 구조.

---

### 2. 503이 그대로 “503”으로 보이는 이유 (프론트)

- **백엔드**는 503과 함께 위 **한글 안내 메시지**를 `response.body.message` 에 담아 보냄.
- **axios**는 4xx/5xx 응답 시:
  - `err.message` → `"Request failed with status code 503"` 로 설정하고,
  - 실제 서버 메시지는 `err.response.data.message` 에 있음.
- **PaymentSuccessPage** 의 catch 블록에서는 **`err?.message`만** 사용하고 있어서:
  - “처리 중입니다”, “S008” 등이 **매칭되지 않고**,
  - 화면에는 **“Request failed with status code 503”** 만 노출됨.

정리하면, **503의 “의미(처리 중, 재시도)”는 백엔드에서 잘 보내주고 있지만, 프론트에서 서버 메시지를 쓰지 않아 503 숫자/문구만 보이는 상황**입니다.

---

### 3. 그 외 가능성 (참고)

- **프록시/게이트웨이 타임아웃**  
  토스 API 응답이 느릴 때 우리 백엔드가 오래 대기하면, 앞단 프록시가 503을 반환할 수 있음.  
  코드 상으로 확인된 주된 원인은 위 1·2번입니다.

---

## 대응 요약

| 구분 | 내용 |
|------|------|
| **백엔드** | 503 + “처리 중” 메시지 반환은 **재시도 유도용으로 적절**함. 변경 불필요. |
| **프론트** | 503/에러 시 **`err.response?.data?.message`** 를 우선 사용해 서버 메시지를 표시하고, “처리 중”/S008이면 **자동 재시도**가 되도록 수정. |
| **추가** | 503 상태 코드 자체도 “처리 중”으로 간주하고 재시도하도록 하면, 메시지가 빠져도 503만 보이는 상황을 줄일 수 있음. |

위와 같이 **PaymentSuccessPage** 에서 에러 메시지 추출 방식과 503 시 재시도 로직을 수정하면, “토스 결제는 됐는데 503만 보인다”는 현상이 해소됩니다.
